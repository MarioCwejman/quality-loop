Install

Claude can tell you it works before anything has run. This layer checks every file as it is written, and won’t let a session end until the code has actually been run.

Four hooks, three reviewers and four skills for Claude Code. Two commands to install. Needs Node on your PATH.

What actually changes

The same work, with the plugin installed and without it.

Default Claude Code

  • Can end a turn saying it works, having run nothing
  • A syntax error surfaces three edits later
  • Describes the interface it just built
  • You re-explain the project’s stack every time
  • May create a file that silently disables your AGENTS.md
  • Lessons disappear when the session ends

With quality-loop

  • Blocked from finishing if it edited code and ran nothing
  • The language’s own checker runs on every file write
  • A separate reviewer opens the page and looks at it
  • /bootstrap detects the stack and writes the rules once
  • Warned at session start; bootstrap refuses to create one
  • /retro promotes a lesson to a rule on its second occurrence

What’s in it

Eleven pieces in three groups. The hooks run by themselves; the reviewers and skills wait until you need them.

Hooks — these run on their own

verify-edit

after every file write

Runs the real checker for that language — Node, Python, shell, Luau, TypeScript — and reports what it found. It won’t reformat your file or block you.

stop-gate

when Claude tries to finish

Refuses the ending if code was edited and no test, gate or screenshot was ever run against it.

track-verification

after every command

Notices when something real was run, so the stop-gate knows the work was checked and stays quiet.

session-start

when a session opens

Warns if a CLAUDE.md is suppressing your AGENTS.md, and suggests /bootstrap in a project with no setup.

Reviewers — a second opinion on work they didn’t write

art-director

after visual work

Opens the running page, captures it at two widths, and judges it against your project’s own brief. It reports back rather than editing.

code-reviewer

before committing

Reviews the local working tree. Needs no GitHub remote, so it works on a repo that never leaves your machine.

luau-reviewer

after Roblox scripts

Remote boundaries, instance lifetime, Rojo tree correctness. It turns down non-Roblox Lua, which is a different language.

Skills — type the slash command when you want them

/bootstrap

once per project

Detects the stack, asks a few questions, and writes a tailored setup. Six profiles: Roblox, Node, Python, .NET, static sites, unknown.

/retro

after a rough session

Turns a recurring problem into a rule, but only after it has happened twice, and writes it at the narrowest scope that still holds.

/ingest

when you find a reference

Files a screenshot, link or observation into your notes vault with its source, and writes down the part you can reuse.

/vault-lint

when the inbox builds up

Audits those notes for missing sources, stale captures and duplicates. Reports and proposes; never curates on its own.

What it found on the first real project

A Path of Exile 2 build tool with a pinned calculation engine. Its test suite had been reporting a clean run for months.

The vendored engine directory was owned by a different Windows account, so git refused to read it, so the commit-pin check raised inside setUpClass — which aborts an entire test class before any of its tests run. The suite reported on what was left and said nothing about the rest.

149

tests reported before, 32 of them erroring

247

tests actually there, all passing once the cause was fixed

98

tests that had never run at all, and never appeared in a count

Install

Two commands. The first tells Claude Code where to look, the second installs from there.

# from the folder holding this plugin
claude plugin marketplace add ./dist
claude plugin install quality-loop@mario-local
