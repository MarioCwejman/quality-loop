Install

Two commands, then restart the session.

  1. Check Node is available

    Every hook is a small Node script. If this prints a version you’re fine; if it doesn’t, install Node first — nothing else will work.

    node --version

  2. Point Claude Code at the folder

    Run this from the directory that contains dist/. It registers a local marketplace — just a folder Claude Code knows to look in.

    claude plugin marketplace add ./dist

  3. Install the plugin

    claude plugin install quality-loop@mario-cwejman

    Check what landed:

    claude plugin details quality-loop@mario-cwejman

    You should see four skills, three agents and three hook events.

  4. Start a new session

    Skills, agents and hooks are read when a session opens. Nothing you just installed is visible to a session already running.

If you already set these up by hand, remove them first. Hooks declared in ~/.claude/settings.json and hooks from a plugin both fire. With both in place every file write gets checked twice and the stop-gate runs twice. Delete the hooks block from settings.json, or leave the plugin disabled and keep using the hand-installed copy.

The four hooks

These run by themselves. You never invoke them, and three of the four are silent unless something needs saying.

HookRunsWhat it does
verify-edit after a file is written Runs that language’s syntax checker and reports problems. Report-only: it never blocks and never reformats, because rewriting a file Claude just wrote breaks its next edit.
track-verification after a command or MCP tool Records that something real was run. Silent always — it exists so the stop-gate knows your work was checked.
stop-gate when Claude tries to end its turn Blocks the ending if code was edited and nothing was run against it. The only hook that can interrupt you.
session-start on open, resume or clear Reports an AGENTS.md being suppressed, suggests /bootstrap in a project with no setup, and mentions a notes inbox once it passes ten items.

Which checker runs

verify-edit picks by file extension, and only runs a tool that is actually installed. A missing tool is skipped silently rather than reported as a failure.

  • .js .cjs .mjs — node --check
  • .py — a syntax-only parse that writes no __pycache__
  • .sh .bash — bash -n
  • .luau .lua — luau-lsp analyze, but only in a project that is genuinely Roblox
  • .json — parsed, so a trailing comma is caught immediately

For tools a project can adopt or not — a formatter, a linter — the hook looks for the config file first and stays out of it if there isn’t one. It will not introduce a tool you never chose.

Satisfying the gate

The stop-gate is the piece you’ll actually interact with, so it’s worth knowing what clears it.

Anything that genuinely exercises the code counts: a test runner, a build, a type-check, a linter, running the script directly, or a screenshot through a browser tool. Reading a file doesn’t count. Neither does git status.

CountsDoesn’t count
npm test, pytest, cargo test, go testls, cat, git status
node --check x.js, bash -n x.shopening the file
python x.py, node x.mjs, bash x.shdescribing what the change does
a browser screenshotsaying it should work

When you genuinely can’t verify

Sometimes there’s nothing to run — the change needs Roblox Studio open, or credentials you don’t have, or hardware that isn’t here. That’s a legitimate ending. Claude should say so in one line and stop, rather than claiming it works.

The gate exists to catch verification that was skipped, not to make you run something for its own sake.

The reviewers

Three agents that read your code but didn’t write it. Claude pulls them in on its own when the work matches; you can also ask for one by name.

art-director

Use this when a screen looks templated, or when you want to know whether it matches the brief. It opens the running page, captures it at two widths, reads your project’s brief and reports against it. It does not edit anything.

It needs the page actually running, so start your dev server first. If it can’t capture a screenshot it says so, rather than reading the source and implying it looked.

code-reviewer

Reviews uncommitted work in your local tree. Useful on a repo with no GitHub remote, where a PR-based review isn’t an option.

luau-reviewer

Roblox-specific: remote boundaries, instance lifetime, whether the Rojo tree maps the way you expect. It declines non-Roblox Lua, because a LuaJIT or Love2D file is a different language with different rules.

The skills

These wait until you ask. Type the slash command.

/bootstrap

Run this once in a new project. It detects the stack, asks a few short questions, and writes a setup tailored to what’s actually there — not a template.

What it will not do: create a CLAUDE.md in a repo that has an AGENTS.md, because that silently switches the AGENTS.md off. It also won’t add a formatter, linter or framework the project hasn’t already adopted, and it will tell you what it chose not to generate and why.

Six profiles ship with it: Roblox/Luau, Node web, Python, .NET, static sites, and one for a project it can’t place.

/retro

Run after a session that went badly. It looks at what actually went wrong and proposes changes.

Most of its value is in what it declines to do. A problem seen once is recorded as an observation and nothing else changes. It becomes a rule only on a second, independent occurrence, and it is written at the narrowest level that still holds — a quirk from one project, promoted to a global rule, becomes wrong advice in the next one. It also proposes deletions, which matters: an out-of-date rule still gets followed.

/ingest

For capturing a reference — a screenshot, a link, an observation — into your notes vault. It records where the thing came from and writes down the part you can reuse, so the file still means something in three months.

/vault-lint

Audits those notes: missing sources, captures that have sat unfiled for weeks, broken links, duplicates. It reports and proposes; it won’t file or delete anything on its own.

When something’s wrong

Claude says something confidently wrong about your project

Check the rules first. A path-scoped rule that matches too broadly will pull in advice meant for a different stack — Roblox guidance landing on a LuaJIT file, for instance. Ask which rules are loaded and look in the project’s .claude/rules/. This is easy to miss, because a misfiring rule looks the same as Claude simply being wrong.

Everything seems to happen twice

You have hooks in both settings.json and the plugin. Keep one.

A skill or agent you just added isn’t there

They’re loaded when a session starts. Restart the session.

The gate won’t let you finish and there’s nothing to run

Say so — that is an accepted ending. If it keeps firing on files that were run, the pattern list in track-verification doesn’t recognise your command yet. Worth fixing rather than working around, or the gate stops being worth listening to.

A hook reports a file that plainly exists

On Windows, bash may resolve to WSL’s copy rather than Git Bash, and WSL reads a C:/… argument as a Linux path. The shell gate avoids this by passing scripts on standard input instead of by path.

Known limits

What this does not do.

It can’t carry your rules or your global instructions

A plugin can hold skills, agents, commands, hooks and MCP servers. There is no mechanism for rules/ or a global CLAUDE.md, so those still have to be copied by hand onto a new machine. This is most of a setup, not all of one.

The packaged hooks have not been run end to end

The plugin’s structure validates and its inventory loads correctly. The hook scripts are well tested on their own, but have not been run from inside a plugin, where their paths resolve differently. Until they have, keeping the plugin disabled and using the hand-installed copies is safer.

It adds latency and context

A checker runs on every file write — usually well under a second, occasionally a few. The components also cost roughly 980 tokens in every session before you do anything. Small, but not nothing.

Rules decay

Guidance that was true when written stops being true. /retro prunes, but only when you run it. So the maintenance is reactive — when Claude says something odd about your code, check the rules.
